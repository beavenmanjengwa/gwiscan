============================================================================================
GWIscan — PROJECT DIRECTORY LAYOUT
============================================================================================

GWIscan runs against a project directory (-C / --workdir; default: the current
directory). Inputs, config, and reference databases live under it. Results and
logs are written under it too, or to a separate directory given with -o / --output.


DIRECTORY TREE
--------------------------------------------------------------------------------------------

  /data/myproject/              project directory (-C / --workdir)
    config.yaml                 run settings: MODE, THREADS, EBI_EMAIL, OUTPUT, ...
    config/
      family.tsv                family table            (MODE: family)
      superfamily.tsv           family table + rollup   (MODE: superfamily)
      architecture.tsv          domain-combination rules(MODE: architecture)
      species.tsv               species manifest        (multi-species runs only)
    input/
      proteome.fasta            input proteome
      annotation.gtf            optional genome annotation (.gtf / .gff3 / .gff)
    db/
      hmm/                      custom HMMs; Pfam-accession HMMs download here
      blast/                    BlastModel reference FASTAs (one per family)
      go/                       go-basic.obo cache (GO id -> name)
    final_results/              deliverables: final TSV/XLSX, members GFF3, provenance
    intermediate/               every stage's working files
    logs/                       per-stage logs

  final_results/, intermediate/ and logs/ move to -o / --output when it is given;
  inputs, config, and db/ are always read from the project directory.


KEY FILES
--------------------------------------------------------------------------------------------

  config.yaml         Run settings. Sits at the project root, not inside config/.

  config/*.tsv        The config table follows MODE — provide the one that matches
                      and keep MODE in config.yaml in agreement:
                        family.tsv        MODE: family        (flat list of families)
                        superfamily.tsv   MODE: superfamily   (adds a Superfamily column)
                        architecture.tsv  MODE: architecture  (domain-combination rules)
                      Copy the matching *.tsv.example and edit.

  config/species.tsv  Species manifest (Prefix, Proteome, optional Annotation). Its
                      presence switches `run` to multi-species mode.

  input/proteome.fasta  The input proteome for a single-species run.

  input/annotation.*  Optional. Genome annotation (.gtf / .gff3 / .gff) matching the
                      proteome, one transcript per gene. Adds each member's chromosome,
                      start, end, strand and intron count. Absent -> the coords stage
                      is skipped and those columns are omitted.

  db/blast/           One BlastModel FASTA per family — the DIAMOND query, run for
                      every family.

  db/hmm/             Custom HMMs you place here; Pfam-accession HMMs are fetched on
                      first setup-db and an existing file is reused (offline runs). A
                      custom identifying HMM must declare GA thresholds.

  db/go/              go-basic.obo cache, fetched on first run and reused.


RUNNING
--------------------------------------------------------------------------------------------

  Single species:
    gwiscan run -C /data/myproject --threads 8 --ebi-email you@example.com
    Uses input/proteome.fasta and the MODE config table, plus input/annotation.* if
    present.

  Multi-species:
    Add config/species.tsv, then run the same command. Each species writes into its
    own final_results/<Prefix>/ and intermediate/<Prefix>/. Annotation is an optional
    third column giving that species its own GTF/GFF3.

      Prefix   Proteome                  Annotation
      Ath      genomes/Athaliana.fasta   genomes/Athaliana.gff3
      Gma      genomes/Gmax.fasta

  Separate output directory:
    gwiscan run -C /data/myproject -o /scratch/gwiscan_out ...
    Results and logs go under -o; inputs, config, and db/ stay in the project directory.
